# 0022. Kit store: UI kits from a registry, added to a team in one click

- Status: accepted
- Date: 2026-11-15
- Deciders: Ziyang (lead maintainer)

## Context

Designers start from kits: a design system, an icon set, a wireframing kit. Figma has a UI kits list (Assets → UI kits) and its Community; Penpot has a [libraries and templates hub](https://penpot.app/penpothub/libraries-templates) whose files live in the public repository penpot/penpot-files and are served from `penpot.github.io/penpot-files`. Drawpane already imports `.penpot` exports (decision 0014's sibling, `@drawpane/penpot`), has built-in and team templates on the New file page, and team libraries (decision 0010). What it lacked was a place to find kits and a way to add one without downloading and re-uploading a file.

Two things constrain how. The page's Content-Security-Policy allows `connect-src 'self'` and `img-src 'self'` only, so the browser can't fetch a list, cover or file from GitHub or Penpot itself. And Penpot's hub has no machine-readable index: its files are in a repository, and its pages say who made each one.

## Decision

- **A registry, separate from the app:** [Joinpane/drawpane-kits](https://github.com/Joinpane/drawpane-kits), whose `index.json` lists every kit in one shape. An instance reads it from `KIT_REGISTRY` (by default the registry's `main` on raw.githubusercontent.com), so a self-hoster can point at their own copy, or set `off` to turn the store off.
- **Penpot's hub is passed through, not curated.** A scheduled workflow in the registry rebuilds Penpot's part of the index daily from Penpot's own data: every `.penpot` file in penpot/penpot-files (with its size and git blob SHA-1), the `<name>.LICENSE` file beside it where there is one, and from the hub's page for it its title, author, description, categories, cover and dates (the page's schema.org `CreativeWork` and its download link). Nothing is renamed, edited or left out; hub pages whose download isn't a file in the repository are listed without a file. Files are never copied into the registry: entries point at Penpot's public hosting, where they're fetched when someone adds the kit.
- **Licences are shown as their source gives them.** A Penpot entry with a LICENSE file shows it (a link, and its text under "Read the licence"); one without says "Licence not stated by the author: see Penpot's hub", linking the entry's hub page. The author and Penpot's hub are credited as the source.
- **Kits hosted in the registry follow rules** (`kits/<id>/kit.json`, for kits Drawpane converts later, such as Material 3): one of MIT, Apache-2.0, CC BY 4.0, CC BY-SA 4.0, OFL-1.1, MPL-2.0 or CC0, an attribution that names the kit, its author and (for CC BY) the licence with its link and that it was converted, a file of at most 25 MB with its sha256, and a 1390 × 724 cover rendered with Drawpane. The registry's CI checks every one, and that `index.json` is what its sources make. The app checks the same rules again when it reads the index, and leaves out an entry that breaks them.
- **The Worker fetches for the page, and only what the index lists.** `GET /api/kits` returns the index; `/api/kits/:id/cover` and `/api/kits/:id/file` fetch the cover or file the configured index names for that kit (relative URLs resolve against the index), so this is no open proxy. All need a signed-in person. The file streams through with `cache: no-store` and `Cache-Control: no-store`: the server never keeps it.
- **The browser checks the file** against the index before importing it: its size and its sha256, or for files in a git repository (Penpot's), its git blob SHA-1, which GitHub's API reports and Pages serves from the same commit. A mismatch is refused ("The downloaded file isn't the one the store lists"). A Git LFS pointer, which is what Pages serves for a file kept in LFS, is explained rather than imported.
- **Where it lives in the app:** **Kit store** in the dashboard's sidebar, a team page beside Fonts and Members, with a search (⌘K), a filter by kind (UI kits, libraries, templates, icons, wireframes) with counts, and cards with the kit's cover, name, kind and author. The New file page links to it below Templates. A card opens the kit's details: cover, author, categories, description, source, licence, credit and size.
- **"Add to team" is one click.** It downloads (with progress), checks, and imports with the existing Penpot importer into the team's **Kits** project (made on first use, so kits stay together, like libraries, instead of filling Drafts). Then it offers **Open** and, for a kit with components, **Publish as team library** (decision 0010), which publishes it with the note "Added from the kit store". Viewers can browse; editors add.
- **The credit travels with the file.** The import puts an "About this kit" frame on the file's first page, above its content: the kit's title, its author (or the registry's attribution), its source, its licence as given, and "Converted to Drawpane from <file> on <date>. Some parts may differ from the original." A credit in the store alone would be lost when the file is copied or exported.
- **"Added".** `team_kits` records which kits a team added and the files they became; the store marks those kits "Added" (as Figma does), until their file is moved to the trash.

## Consequences

- Opening the store makes the instance fetch the registry's index (cached for ten minutes per Worker isolate); adding a kit makes it fetch the kit's file from its host. Browsers contact only the instance.
- Penpot's listing is as good as Penpot's data: an entry whose hub page is missing shows its file name and no cover; a hub entry without a file can't be added and links to its page instead; a file Penpot keeps in Git LFS can't be downloaded from Pages.
- Licences are the kit's author's business, shown as stated. The store doesn't judge whether a kit without a stated licence can be used.
- Kits are converted by the Penpot importer, so they share its fidelity notes (shown after adding, as after an import). A sweep over every file Penpot listed on 2026-11-15 (142 files): the 91 in Penpot's current format (zip, binfile v3) all convert, with notes most often about design token sets (29 files), images missing from the export, auto layout margins and space-around/evenly, skewed layers and boolean groups. The other 51 can't be imported: 50 are in Penpot's older binary format (binfile v1, zstd and Fressian), which `@drawpane/penpot` doesn't read, and one is a Git LFS pointer. The registry records each file's format (`container`, read from its first bytes), so the store marks those "Penpot only" and offers their page instead of failing on Add. Reading binfile v1 is future work.
- Building the store found two bugs, fixed with it: text that wraps in a box narrower than one character looped forever (a word broken between characters could cut nothing and start again), and a file filled by an import couldn't be versioned or published until someone opened it (the import now tells the file's room which file it is).
- Large kits (Penpot's largest export is over 80 MB) take a while to download and convert in the browser, and are bounded by the import endpoint's 64 MB of converted nodes.

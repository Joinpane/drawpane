# 0020. SVG: imported as layers you can edit, or drawn to a PNG for a fill

- Status: accepted
- Date: 2026-11-15
- Deciders: Ziyang (lead maintainer)

## Context

Icons, logos and illustrations travel as SVG: "Copy SVG" in icon sets, "Copy as SVG" in Figma, exports from Illustrator and Inkscape. Drawpane refused them ("Drawpane takes PNG, JPEG, WebP and GIF images"), while the image fill picker's hint claimed SVG. An SVG is also a document, not a picture: it can carry scripts, event handlers, CSS that fetches things, and references to other files, so it can't be stored and served as media the way a PNG is.

Figma treats an SVG placed on the canvas as layers: a frame named after the file, holding groups, shapes and vectors with their paints, all editable. As an image fill, Figma takes raster images only.

## Decision

- **On the canvas, an SVG becomes layers.** Dropping, pasting or choosing an `.svg` file, and pasting SVG markup as text, places one frame per SVG, named after the file ("SVG" for pasted markup), sized to its width and height (else its viewBox, else 300 × 150, as browsers do), at the drop point or the viewport's centre like images, selected, in one undo step. A drop that mixes SVGs and images places them side by side; only the images upload.
- **The conversion is a package of its own, `@drawpane/svg`**, beside the Figma and Penpot importers and sharing their geometry (`@drawpane/import-kit`: path parsing to absolute cubics, affines, boxes in a frame's space, notes). It works on a parsed DOM, so it runs in the browser and, with jsdom, in unit tests.
- **Native layers where the model has the kind:** `<g>`, `<a>`, `<switch>`, nested `<svg>` and `<use>` to groups (a plain wrapper of one layer is dropped, and one holding only a shadow or opacity hands it to its layer), `<rect>` to rectangles (one corner radius; unequal rx and ry become a vector), `<circle>` and `<ellipse>` to ellipses, `<line>` to lines, `<path>`, `<polygon>` and `<polyline>` to vectors, `<text>` to text. Layers are named by Illustrator's `data-name`, Inkscape's label, a `<title>` or the `id`, else by kind.
- **Transforms land in the box where a box can say them** (position, size, rotation, flip), including the viewBox with `preserveAspectRatio`; a skew, or a rounded rectangle stretched unevenly, is baked into a vector's points, exactly.
- **Paint and stroke come from the computed style**, cascaded as a browser does: presentation attributes, `<style>` rules by specificity (with `element.matches`), `style=""`, `!important`, inheritance and `inherit`. Colours in every CSS form; `currentColor` is the `color` property, black without one. Strokes are centred, with width, caps, joins and dashes scaled by the transform. Opacity goes on the layer, `fill-opacity` and `stroke-opacity` on the paint, `mix-blend-mode` on the layer.
- **Gradients are placed exactly where the model can say them.** Drawpane lays a gradient out in its layer's unit square (decision 0013); the SVG gradient's own coordinates (units, `gradientTransform`, `href` templates) are mapped into that square. A linear gradient always comes across exactly. A radial one does whenever that mapping keeps circles round (bounding-box units on an unrotated shape, user-space units on a square one); otherwise its circle is averaged, as is an off-centre focal point, and the import says so.
- **Clip paths and masks become Drawpane masks**, first in a "Clip group" or "Mask group" with what they clip: a one-shape clip as that shape, several as one outline; a white mask as an outline mask, otherwise luminance or alpha as the SVG says. A clip to the whole frame (Figma's exports wrap everything in one) is dropped, since the frame clips anyway.
- **Filters that are effects become effects:** `feDropShadow`, a lone `feGaussianBlur` (layer blur, radius twice the deviation, decision 0013), and Figma's own drop and inner shadow chains with spread.
- **What can't come across is left out and named, once:** other filters, patterns (their fallback colour is used), embedded images, `foreignObject`, markers, dash offsets, positioned text spans. One notice after the import lists them in plain words ("Some parts are approximated: 1 filter effect was left out, 2 gradients were approximated."), as the Figma and Penpot importers' summaries do.
- **Safety:** the markup is parsed by `DOMParser` as `image/svg+xml` into a detached document that's never attached to the page, so nothing in it runs or loads; markup that isn't well-formed XML (an undeclared `xlink:` prefix, an HTML entity) gets a second, forgiving parse as HTML, also detached. Scripts, event attributes, `foreignObject` and references to other files are never read; `<style>` at-rules are skipped, so `@import` fetches nothing. Files are capped at 10 MB, documents at 50,000 elements, and imports at 5,000 layers (so `<use>` can't multiply a small file into millions), each with a sentence saying so.
- **As an image fill, an SVG is drawn to a PNG** in the browser, through an `<img>` (where an SVG can't run scripts or load anything), at twice its own size with the longest side at most 4096 px, and that PNG uploads like any image. The server's media rules are unchanged: storage only ever holds PNG, JPEG, WebP and GIF.
- **Measured:** a Playwright suite (`apps/web/e2e/parity/svg.spec.ts`) pastes each SVG of a hand-made corpus (a stroked icon with `currentColor`, a Figma card with gradients, a shadow and clip paths, an Illustrator export with `<style>` classes and transforms, an even-odd logo, a flag built from `<use>` and `<symbol>`, and units, dashes and a skew), draws it with Drawpane's renderer and the original with the browser, both at 2×, and compares pixels. Mean difference over RGB (0–255), 99th percentile in brackets: icon 0 (0), Illustrator badge 0 (0), flag 0 (0), units and dashes 0.03 (0), Figma card 0.28 (2), even-odd logo 0.51 (27). The two renders are the same rasteriser drawing the same geometry; what's left is the shadow's blur and the edges of arcs, which Drawpane stores as cubic curves. Each fixture's threshold is that score with some room, so a conversion that drifts fails CI.

## Consequences

- An SVG on the canvas is no longer the file it came from: exporting it again gives Drawpane's SVG, not the original markup. As in Figma.
- Text is placed from its baseline with an estimated ascent, in the font it names when Drawpane has it; positioned spans, `textPath` and per-glyph rotation are approximated.
- Drawpane has no miter limit, so a sharp miter join that SVG's limit of 4 would bevel stays pointed (canvas's limit is 10). Icons use round joins, so this is rare.
- An SVG fill is a picture of the SVG at the size it was chosen; it doesn't stay sharp past 2× its own size or 4096 px. Placing the SVG as layers and masking it does, when that matters.
